# Saving originals

The archive opens an existing archive for writing with `openArchiveWriter`. It takes the archive information from an earlier open. Commands opens that writer and passes it to capture. Capture does not read folder settings. The writer exposes `saveOriginal`, `sourceHeld` and `close`. It queues saves in the same session and holds the write lock until the queued work and close finish. Commands calls `close` only after capture has returned its final outcome. Capture does not. A new original returns `saved-original`. A source ID that is already held returns `already-held`, and says whether the bytes differ. Capture relies on those two results, and on `manifest-changed`, `evidence-missing`, `writer-stopped`, `writer-closed` and `save-unavailable`.

| Rule | Passes when |
| --- | --- |
| **Captured record version 1.** The [shared contract](../../contracts/captured-record.md) defines the input. A missing, extra or invalid field, or a newer version, is refused before any writing. The version is checked before the fields, so a newer version is reported regardless of its fields. The captured record and manifest entry code live in [contracts](../../contracts/CONTEXT.md). | The shared shape tests accept valid records and reject malformed or newer ones. “Invalid or newer records write nothing, including an unfinished manifest tail” checks the archive boundary. |
| **Original bytes and names.** Save the payload byte for byte. The permanent record ID is the lowercase SHA-256 of the UTF-8 source ID. The lowercase SHA-256 of the record ID is the file name, in a subfolder under `originals/` named by its first two characters. The ending is `.eml` for `message/rfc822`, `.txt` for `text/plain`, `.json` for `application/json`, and `.bin` otherwise. These are ordinary files. | “Original fixtures are byte-exact, use media endings and are appended to the manifest” compares the files and entries. “Source IDs are exact and filesystem names contain only a hash and the media ending” covers path fragments, Windows reserved names, long text and non-English text. |
| **A caller can reuse its buffer.** Saving takes a copy of the bytes before returning control to the caller. | “The writer owns a byte copy before the caller can reuse its buffer” changes the input and checks the file and manifest hash. |
| **File first, then manifest.** Write the payload to an exclusive temporary file in the evidence folder and flush it. Put it in place without replacement, then append and flush the manifest line. Only a complete line holds an item. A complete line read back after a write, flush or close error is reported as held, with a notice. | “The final move cannot replace a file that appears during placement” keeps a competing file intact. The real-writer kill cases verify the states before and after each write and flush. “A system error after writing the complete line reports held and stops the writer” and the cases for errors flushing or closing the manifest verify the notice, stopped writer and repeat after reopening. |
| **Only an unfinished tail can be removed.** Bytes after the last complete line end stay in place until a new original is about to be saved. Recheck the manifest immediately before trimming. Only those unfinished bytes are removed. | “Opening leaves a partial line alone and saving trims only that unfinished tail” compares the bytes. “The manifest is rechecked immediately before removing an unfinished tail” preserves a line completed from outside. Real-writer stops before and after the trim keep every complete line. Invalid records and repeats also preserve the tail. |
| **Opening for writing checks the whole manifest.** An unreadable line or unsupported version blocks writing, as does a repeated record ID within its kind, repeated path or repeated source ID, or a mismatch in the derived record ID or path. Each refusal names its reason. The writer also refuses a manifest it cannot open or a manifest identifying a different archive. When the evidence folder is missing, opening returns the same missing-folder result as saving. It changes nothing during these checks. When saving, another entry already using the file-name stem also causes refusal. | “A complete bad line blocks opening and preserves the entire manifest,” “Opening for writing names each manifest refusal without changing the file,” “Opening for writing checks archive identity and reports an unavailable manifest” “Opening for writing reports a missing evidence folder by its path” and “A used file-name stem is refused even when the entry has a different ending” check the named results and unchanged files. |
| **Leftovers are kept.** Files with the same hash name belong in the record's own subfolder, whose name comes from that hash. Adopt a file there only if its full name and bytes match, and flush the file and its subfolder before indexing it. Move other files with the same hash name to a free name in `leftovers/`, then write new bytes if no match was adopted. A different ending causes a move even if its bytes match. A leftover is never renamed in place, replaced or deleted. The move keeps its bytes under a new name before removing the old name. | “An identical leftover with the exact file name is adopted without replacing it” and “Every differing leftover is kept, including identical bytes with a different ending and an occupied leftovers name” check the adopted file’s flush and identity, plus the kept locations and bytes. A real-writer stop after linking a leftover proves both names are recoverable. “The record subfolder is flushed before indexing an adopted leftover” checks that directory flush on Linux. “Directory names are flushed before indexing a new original or removing a kept leftover name” verifies the flush order on Linux. |
| **Exact repeats are refused.** The writer loads all source IDs on open and compares them exactly, including case, accents and spaces. With the expected manifest and an active writer, a repeat returns the first record ID and writes nothing, even if the media type differs. The result says whether the bytes differ when the original could be read. Different IDs keep separate originals even when the bytes match. | “A held source ID returns the first record ID and compares bytes without writing after reopen,” “When a held original cannot be read, the repeat reports only that and writes nothing” and “Source IDs are exact and filesystem names contain only a hash and the media ending” verify the outcomes and contents. |
| **Is this source ID held.** `sourceHeld` takes a source ID and returns `held` with that record's ID, or `not-held`. It returns `manifest-changed`, `evidence-missing`, `writer-stopped` and `writer-closed` in the same situations as saving. When the manifest cannot be read, it returns `save-unavailable`, the same result saving returns for that, and that stops the writer. `evidence-missing` is the missing-folder result. It writes nothing and does not read the saved file. | A held source ID returns its record ID, and a source ID that is not held returns `not-held`, with the manifest and the files unchanged. A changed manifest, a missing evidence folder, a stopped writer and a closed writer return those same results as saving. A manifest that cannot be read returns `save-unavailable`. The saved file is not opened. |
| **One writer per archive ID.** Hold a listening endpoint from Node's `net` module for the session. Windows uses a named pipe and Linux an abstract Unix socket. The endpoint name uses a hash of the archive ID. No lock file or network port is used. The endpoint accepts no work and closes connections at once. A second writer is refused when starting, and the endpoint goes away when the process ends, including when killed. Copies with the same archive ID contend as well. Opening is refused on systems where the endpoint cannot be made, including macOS, and on any other lock error. | “Two real processes contend even before saving and the lock releases immediately after a kill” checks aliases, refusal, the operating system error, connections and restart. “A lock error other than contention refuses all writing and does not disclose the endpoint” checks a separate lock error. “An unsupported endpoint refuses the writing session before the evidence folder is checked” and “Another writer is refused after a completed save until the writing session closes” verify both limits. |
| **Check for external changes.** At the start of a save and again before trimming and before appending, compare the manifest’s file identity, size and last line with the writer’s view. For a record with an accepted shape and version, a save starting after an outside change reports that the manifest changed, even for a repeat. Refused shapes or versions never touch the manifest or stop the writer. A missing evidence folder is reported as missing. An outside change stops the writer. | “Refused records leave an outside manifest change unchecked and the writer active,” “A manifest changed between two saves stops the writer for either size or last-line change,” “A missing evidence folder is reported as missing when checking the manifest” and “The manifest is checked again after the original is placed and before appending” verify these results. |
| **When a writer stops.** A manifest change, a failed manifest step or a program fault during one stops the writer for the rest of its session. This includes a failed tail truncate or its flush, and a failed append, flush or close. Later saves get a stopped result naming the earlier step without attempting the new record. A result reports an item as held only when its whole line, including its line end, was read back. If the complete line remains after an outside change, a failed flush or a failed close, the notice describes what happened and says the writer stopped. If a flush fails and an outside change is also found, the notice names both. | The tests for an incomplete append, failed tail truncate and failed tail flush check the stopped result. The tests for a missing entry and matching bytes without a line end check that the writer never reports those entries as held. The complete-entry tests check the held notice and a stopped writer after an outside append, a flush or close error, and a flush error with an outside append. |
| **Program faults are raised.** Results name the checked subject and describe the result. Program faults are raised as faults. | “Every original writer message identifies its file, folder, record ID or archive ID and gives no advice” checks each writer message. The program fault tests cover manifest opening and I/O, comparing a repeat, opening the lock and reading back after a manifest error. They check that faults affecting a manifest step stop the writer before the fault is raised. |

The endpoint does not coordinate across computers or across separate running systems, such as a virtual machine or a Linux environment on Windows. On Linux the abstract socket is also separate for programs kept apart by a container or sandbox with its own network namespace. The manifest check does not detect a same-size edit confined to earlier lines or prevent another system from writing after the check. An outside edit that shortens earlier content after an append can move the complete line before the readback search. The writer may report that the manifest changed although the line is there. On Windows and Linux an identical read-only leftover that cannot be opened for flushing is reported and stays unindexed. Publishing and moving files use hard links and require a file system that supports them. The tests kill the writing process. They do not simulate a power cut or a failed disk. Windows skips flushing directory names because Node cannot open a directory there for that operation. A killed process may leave temporary file names in the original's shard. They are never treated as originals or manifest entries.
